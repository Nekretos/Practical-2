## Частина D. Висновки

Обсяг — 150–300 слів. Висновки спираються на власні спостереження.

**D.1.** Що з поведінки сервера виявилося неочевидним або несподіваним. Конкретно, з посиланням на рядок виводу.

Несподіваною виявилася реакція сервера на будь-яке стороннє ім'я в полі Host (проби A.3.1, A.3.2) та на запит версії 1.0 без нього (A.3.3). Замість очікуваної помилки 404 чи 421 вхідний nginx/1.30.1 повернув статус 302 Found і перенаправив запит на інший піддомен з явним зазначенням внутрішнього порту: Location: http://biography.nbuv.gov.ua:3000/. При цьому у відповіді з'явився заголовок X-Powered-By: Express, хоча головний сайт (A.1) віддається через X-Powered-By: PHP/5.4.45 та X-Generator: Drupal 7. Це наочно показало, що за однією адресою працюють два зовсім різні бекенди (PHP та Node.js), а nginx маршрутизує запити між ними. Також цікавим артефактом у виводі A.1 став рядок Expires: Sun, 19 Nov 1978 05:00:00 GMT — зашита в Drupal дата з минулого для надійної заборони кешування.

**D.2.** Яке з полів заголовка викликало найбільше утруднення при визначенні походження (частина B) та з якої причини.

Найважче було класифікувати поля безпеки X-Frame-Options: SAMEORIGIN та X-Content-Type-Options: nosniff. Вони можуть генеруватися як самим рушієм Drupal на боці PHP, так і додаватися проміжним вебсервером nginx через директиву add_header. Оскільки у відповідях від сервісу Express (A.3) цих заголовків не було, за наявними даними неможливо однозначно стверджувати, чи їх генерує код Drupal, чи адміністратори прописали їх в nginx окремо для блоку основного сайту. Через це їхнє походження залишено як «не визначено».

**D.3.** Яке питання залишилося без відповіді після виконання роботи.

Чому в конфігурації nginx для запитів з невідомим або порожнім полем Host сервером за замовчуванням призначено перенаправлення на сторонній порт 3000 (http://biography.nbuv.gov.ua:3000/), а не повернення звичайної помилки або редирект на головний домен бібліотеки?

## Контрольні питання

**1.** У завданні A.1 сервер не надсилав відповіді, доки не було введено порожній рядок. Чим це зумовлено?

За стандартом HTTP кількість рядків заголовка довільна. Порожній рядок (`\r\n\r\n`) слугує обов'язковим маркером завершення блоку заголовків. Поки сервер його не отримає, він вважає запит незавершеним і очікує продовження введення від клієнта.

**2.** Порівняйте результати завдань A.1, A.2 та A.3.1–A.3.3 (таблиця Додатка Д). За яких значень поля `Host` і за якої версії протоколу сервер обслуговує запит, а за яких — ні? Яку задачу розв'язує поле `Host`? Відповідь має посилатися на конкретні рядки ваших виводів.

- Основний ресурс бібліотеки обслуговується (200 OK, X-Generator: Drupal 7) **лише за наявності Host: nbuv.gov.ua** у версії HTTP/1.1 (завдання A.1).
- За відсутності поля Host у версії 1.1 (A.2) сервер взагалі відмовляє в обслуговуванні помилкою 400 Bad Request, оскільки у протоколі HTTP/1.1 цей заголовок є суворо обов'язковим.
- При підстановці чужого або неіснуючого імені (A.3.1, A.3.2) чи у версії 1.0 без поля Host (A.3.3) сервер відхиляє доступ до основного сайту та повертає редирект 302 Found на хост за замовчуванням (Location: http://biography.nbuv.gov.ua:3000/, X-Powered-By: Express).
- **Задача поля Host:** віртуальний хостинг — дає змогу серверу за однією IP-адресою та портом розрізняти, до якого саме з кількох розташованих на ньому сайтів чи сервісів звертається клієнт.

**3.** Скільки відповідей надійшло у завданні A.4 і з якими кодами стану? Чи залежить відповідь сервера на порту 80 від запитаного шляху — і що це говорить про роль цього сервера? Якщо надійшла одна відповідь, знайдіть у ній поле заголовка, яке це пояснює, або зазначте, що такого поля немає. Якщо надійшло дві — що це означає для клієнтської програми, яка завантажує сторінку з великою кількістю вкладених ресурсів?

- Надійшло **дві відповіді**: перша — 404 Not Found (на /opism-pr02-12345 із Connection: keep-alive), друга — 200 OK (на кореневий шлях / із Connection: close).
- Відповідь **залежить від шляху**, що вказує на роль сервера як повноцінного вебсервера контенту (запити обробляє CMS Drupal), а не простого перенаправлювача на HTTPS.
- Отримання двох відповідей означає підтримку постійного з'єднання (keep-alive). Для клієнта це можливість завантажувати сторінку разом з усіма картинками, CSS та JS через одне TCP-з'єднання без витрат часу на повторні підключення.

**4.** Які поля заголовка програма `curl` додала самостійно (завдання A.5)? Ці поля не є обов'язковими — сервер відповів і без них у завданні A.1. З якою метою їх додано?

- Accept: \*/\* — сповіщає сервер, що клієнт готовий прийняти відповідь у будь-якому форматі.
